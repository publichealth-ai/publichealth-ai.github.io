USE CASE 01

Case and laboratory document intake

Convert incoming reports into review-ready surveillance records while preserving source traceability and human validation.

Matched code accelerator Document Eligibility Agent Open GitHub repository

Business need

Move staff from transcription to validation.

Case reports and laboratory results still arrive through scanned forms, faxes, PDFs, email attachments, and other formats that require manual entry. Intake delays slow assignment and investigation, while repetitive transcription creates avoidable quality risk.

This pattern classifies each document, extracts a defined set of surveillance fields, calculates field-level confidence, and routes the draft record to trained staff. The objective is not autonomous case creation—it is faster, more consistent preparation for human review.

  • Shorter time from receipt to an investigation-ready record
  • Consistent capture of required fields and source metadata
  • Clear queues for missing, conflicting, or low-confidence values

Data involved

Design the data contract before the model.

Source documents

Case-report forms, laboratory PDFs, scanned faxes, referral documents, provider attachments, and historical paper records.

Surveillance fields

Condition, patient identifiers, demographics, onset and report dates, provider and facility, specimen details, test method, and result.

Control metadata

Source system, receipt timestamp, document type, field confidence, reviewer decision, correction reason, and record-level audit history.

Operating process

Keep the person in the workflow.

01

Capture

Receive the document through an approved secure channel and retain the original.

02

Classify

Identify document type and select the appropriate extraction schema.

03

Extract

Read required fields and attach field-level confidence and source location.

04

Validate

Present the original beside the draft so staff can confirm or correct values.

05

Load

Post approved data to the surveillance system and monitor corrections over time.

Applied scenarios

Where the pattern fits.

SCENARIO 01

Faxed case report

A scanned disease report is converted into a draft record with condition, onset date, provider, and patient fields ready for review.

SCENARIO 02

Laboratory attachment

A result PDF is associated with the correct case and key specimen and test fields are proposed without changing the source document.

SCENARIO 03

Backlog conversion

Historical records are processed in batches, with low-confidence documents separated for focused manual abstraction.

Implementation guardrails

Controls required for public health data.

1

Protected data boundary

Process protected health information only in approved environments with encryption, access control, and retention rules.

2

Human acceptance

Do not finalize case records or classifications until authorized staff review the extracted data.

3

Source traceability

Keep the original document and make every extracted value traceable to its source location.

4

Quality monitoring

Track accuracy and correction rates by document type, field, sender, language, and population where appropriate.
